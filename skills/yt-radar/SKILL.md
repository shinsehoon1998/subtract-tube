# yt-radar — 해외 트렌드 콘텐츠 소싱 레이더 (cron 자동)

> 호출자: subtract-tube 파이프라인의 cron 트리거(매일 자동) 또는 빼기연구소 크리에이터(수동 1회 실행). 다운스트림 소비자: `yt-script`(이 스킬이 만든 현지화 대본 초안 = yt-script의 '콘텐츠 소스' 입력).
> 목적: **"무엇을 말할까(콘텐츠/주제)"를 소싱**한다. 크리에이터의 실제 방법론은 "콘텐츠(주제)는 한국보다 트렌드가 빠른 **해외 유튜버**에서 가져오고, 구조는 **국내 떡상 영상**에서 가져온다"이다. 이 스킬은 그중 **콘텐츠(해외) 담당**이다. 구조 벤치마크는 별도 스킬 `yt-structure`가 맡는다.
> 핵심 가치: 한국 시장은 해외 AI 자동화 트렌드를 며칠~몇 주 늦게 따라온다. 해외에서 막 뜬 주제를 매일 자동 감지해 **한국형으로 먼저 현지화**해두면, yt-script가 국내 떡상 구조에 얹어 "짜집기"로 빠르게 본편을 찍어낼 수 있다.
> 크리에이터 확정 지시: 사용자가 "일단 해당 부분이 맞으니깐 여기까지 진행해줘"라고 함 — 합의된 1·2단계 설계대로 진행한다.

---

## When to Activate

다음 중 하나면 이 스킬을 켠다.

- subtract-tube **cron 트리거가 매일** 이 스킬을 자동 실행할 때 (기본 동작)
- 사용자가 "해외 채널 신규 영상 확인해줘", "오늘 소싱 돌려줘", "radar 큐 채워줘"라고 할 때
- 새 해외 모니터링 채널을 추가/삭제하는 config 변경 후 재실행할 때

이 스킬은 **콘텐츠(주제) 소싱**만 한다. 국내 떡상 영상의 구조 벤치마크(`yt-structure`), 본편 원고 작성(`yt-script`), 제목/썸네일/TTS/렌더는 범위 밖이다.

## 설정 / 입력 (Config)

모니터링 대상은 사용자가 채우는 config 파일에 둔다. 채널ID 또는 핸들을 적는다.

`subtract-tube/config/radar-channels.yaml` (예시 — 사용자가 자기 채널로 교체):

```yaml
# 모니터링할 해외 유튜버 (AI 자동화/노코드 트렌드 채널 위주)
channels:
  - name: "Nate Herk"          # AI 에이전트·n8n 자동화
    channel_id: "UC..."         # 핸들이면 handle 필드 사용
  - name: "Cole Medin"          # AI 코딩·에이전트 빌드
    handle: "@ColeMedin"
  # - name: "...", channel_id 또는 handle

settings:
  localize_to: "ko-KR"          # 현지화 타겟
  max_new_per_run: 5            # 1회 실행 시 처리할 신규 영상 상한(비용·시간 보호)
  freshness_days: 30            # ⭐ v2: 업로드 1개월 이내만 적재(신선도 필터). 넘으면 자동 스킵
  transcript_lang_priority: ["en", "auto"]   # 자막 우선순위
  whisper_fallback: false       # 자막 없을 때 Whisper STT 폴백(무거움 — 기본 off)
```

> **채널ID 얻는 법:** 채널 페이지 소스에서 `channel_id`(UC로 시작)를 찾거나, 핸들(`@name`)을 채널 페이지 메타에서 channel_id로 1회 변환해 캐시한다. RSS는 `channel_id`만 받는다.

상태 파일: `subtract-tube/config/radar-state.json` — 채널별 **마지막 처리한 영상 ID**와 처리 시각을 저장한다. 신규 판별의 기준점이며, 같은 영상을 두 번 처리하지 않게 한다.

## 파이프라인 (the core flow)

매 실행마다 아래 순서로 돈다. 채널 단위로 반복한다.

### 1) 신규 감지 — RSS 피드 (API 키 불필요)

YouTube는 채널마다 공개 RSS 피드를 제공한다. **API 키·할당량 없이** 최신 15개 업로드를 받을 수 있다.

```
https://www.youtube.com/feeds/videos.xml?channel_id=UCxxxxxxxx
```

처리:
1. 각 채널의 RSS XML을 가져온다(`WebFetch` 또는 `curl`).
2. `<entry>`에서 `yt:videoId`, `title`, `link`, `published`를 파싱한다.
3. `radar-state.json`의 마지막 처리 ID와 비교해 **그 이후의 신규 영상만** 골라낸다.
4. **⭐ v2 신선도 자동 필터:** `published`가 **오늘 기준 `freshness_days`(기본 30일=1개월)보다 오래된** 영상은 자동으로 제외한다. v2 선별 기준이 "주제는 업로드 1개월 이내(신선도)"이므로, 묵은 영상은 신규로 잡혀도 큐에 적재하지 않는다.
5. `max_new_per_run`로 상한을 건다(폭주·비용 보호). 넘치면 오래된 신규부터 우선 처리하고 나머지는 다음 실행으로 미룬다.

> RSS는 자막을 주지 않는다. 신규 목록과 메타데이터만 준다. 트랜스크립트는 3단계에서 따로 뽑는다.
> **뷰트랩 성과도·기여도는 RSS로 못 얻는다.** 뷰트랩 지표는 Chrome 확장 오버레이라 자동 수집 불가다. 따라서 이 스킬은 **신선도(자동)까지만 걸러** 후보를 적재하고, "**성과도·기여도 높음**"(=구조의 힘으로 터질 주제) 여부는 사람이 뷰트랩으로 확인해 큐 레코드의 `뷰트랩 확인` 필드에 메모한다(아래 출력 계약 참조).

### 2) 트랜스크립트 추출 (⚠️ 자막 의존)

신규 영상마다 자막을 뽑는다. 우선순위:

1. **자동자막/캡션** — `youtube-transcript-api`(Python) 또는 `yt-dlp --write-auto-sub --skip-download --sub-lang en --convert-subs srt`. 빠르고 가볍다. **대부분 여기서 끝난다.**
2. **수동 자막**이 있으면 그쪽을 우선(품질 우수).
3. **자막이 아예 없을 때만 Whisper STT 폴백** — `yt-dlp`로 오디오만 받고(`-x --audio-format mp3`) Whisper로 받아쓰기. **무겁다**(다운로드+모델 추론 시간·CPU/GPU 비용). `whisper_fallback: true`일 때만 동작하고, 기본은 끈다. 폴백이 꺼져 있고 자막도 없으면 해당 영상은 `비고`에 "자막 없음 — 수동 확인 필요"로 표시하고 대본 초안 생성은 건너뛴다.

자막을 합쳐 타임스탬프를 제거한 평문 트랜스크립트로 정리한다.

### 3) 현지화 번역 (직역 금지) — ✅ 핵심

> 직역하면 안 된다. **한국 사례·정서·밈으로 치환**한다. 비즈니스PT 원고 톤(공감+정보)을 의식한다.

치환 규칙:
- **해외 도구·서비스 → 한국에서 통하는 등가물 or 그대로 두되 1줄 설명**(예: "내가 미국 결제로 쓰는 Stripe" → 한국 시청자에겐 "토스페이먼츠/포트원 같은").
- **해외 사례·인물·금액($) → 한국 맥락·원화·국내 사례**로 치환(예: "$2k/mo SaaS" → "월 200만 원짜리 외주를").
- **밈·관용표현 → 한국 유튜브에서 먹히는 표현**(직역체 "여러분 안녕하세요" 류 금지).
- 정보의 **사실관계·수치·메커니즘은 보존**하되 포장만 한국형으로. (사실검증은 yt-script 단계 휴먼 체크포인트에서 한 번 더.)
- 톤: 공감(시청자의 문제) → 정보(해외에서 검증된 방법) 흐름. 후킹·구조 완성은 yt-script가 국내 떡상 템플릿으로 마무리하므로, 여기서는 **완성 원고가 아니라 "현지화된 콘텐츠 살(초안)"**을 만든다.

### 4) 출력 — 큐에 적재 + 알림

신규 영상마다 1레코드를 만들어 큐에 누적한다.

## 출력 계약 (Output Contract)

큐 파일: `subtract-tube/drafts/radar-queue.md` 에 **누적**(append)하거나, 일자별로 `subtract-tube/drafts/radar-YYYY-MM-DD.md`에 적재한다. 한 영상 = 한 레코드. 아래 스키마를 고정한다(yt-script가 이 7필드를 그대로 소비한다).

```
## [YYYY-MM-DD] {원제목}
- 채널: {채널명}
- URL: {영상 URL}
- 게시일: {published}
- 한국형 핵심 문제 1문장: {시청자가 가진 단 하나의 문제를 한국어 1문장으로}
- 현지화 대본 초안: |
    {직역 아닌, 한국 사례·정서로 치환한 콘텐츠 살. 공감+정보 흐름. 완성 원고 아님.}
- 뷰트랩 확인: {🙋 사람이 채움 — 성과도·기여도 높음? (예/아니오/미확인). v2 선별 기준: 성과도·기여도 높은 주제만 본편으로. 자동 비워둠 → 크리에이터가 큐 검토 시 메모}
- 비고: {자막 출처(자동/수동/Whisper) · 신뢰도 경고 · 사실검증 필요 항목 등}
```

- `한국형 핵심 문제 1문장`은 **yt-script의 필수 입력**("이번 영상 주제(핵심 문제 1문장)")과 1:1로 연결된다. 결(結) 일치의 기준점이 된다.
- `뷰트랩 확인`은 **사람이 채우는 메모 필드**다. 뷰트랩 성과도·기여도는 자동 수집이 안 되므로 비워둔 채 적재하고, 크리에이터가 큐를 검토할 때 "이 주제가 성과도·기여도 높은가"를 표기해 본편 후보를 추린다.
- `현지화 대본 초안`은 yt-script가 국내 떡상 구조에 얹을 **콘텐츠 원료**다. 완성본이 아님을 `비고`에 명시한다.
- 처리 끝나면 `radar-state.json`의 마지막 처리 ID를 갱신한다.

**알림:** 1회 실행에서 신규가 1건 이상이면 요약 알림을 보낸다(신규 N건 / 채널별 제목 리스트 / 큐 파일 경로). 알림 채널은 사용자가 붙인 것을 쓴다(없으면 콘솔/로그 출력). 신규 0건이면 조용히 종료.

## 스케줄 (cron)

이 스킬은 매일 자동 실행을 전제로 한다. 두 가지 방법:

1. **Claude Code `/schedule`(routine)** — "매일 오전 9시(KST) yt-radar 실행" 형태로 cloud 루틴 등록. 가장 간단.
2. **CronCreate / OS cron** — 로컬·서버에서 cron으로 진입점(예: `claude -p "/yt-radar 실행"` 또는 파이프라인 스크립트)을 호출.

빈도/시간 가이드:
- **기본: 하루 1회.** 해외 채널 업로드는 일 단위라 1회로 충분. RSS·자막은 가볍다.
- 트렌드 민감 시즌엔 1일 2회(오전/저녁)까지. 그 이상은 신규가 없어 낭비.
- 실행 시각은 **해외 채널 주 업로드 시간 + 반나절** 뒤로(예: 미국 저녁 업로드 → 한국 오전)로 잡으면 신규를 놓치지 않는다.
- `max_new_per_run`으로 1회 처리량을 묶어 트랜스크립트/현지화 비용을 통제한다.

## 자동 vs 수동 경계 (꼭 지킬 것)

| 단계 | 분류 | 사람이 할 일 |
|---|---|---|
| RSS 신규 감지 + 신선도 필터(1개월) | ✅ 완전 자동 | 없음(채널 config만 1회 세팅) |
| 뷰트랩 성과도·기여도 판단 | 🙋 수동 | 큐의 `뷰트랩 확인` 필드를 크리에이터가 채움(자동 수집 불가) |
| 트랜스크립트 추출(자막) | ⚠️ 반자동 | 자막 없는 영상은 수동 판단(Whisper 돌릴지 / 스킵할지) |
| 현지화 대본 초안 | ✅ 자동 생성 | **사실검증은 다운스트림(yt-script) 휴먼 체크포인트에서** |
| 큐 적재 + 알림 | ✅ 자동 | 없음 |
| **어떤 후보를 실제 영상으로 만들지 선택** | 🙋 **수동** | 크리에이터가 큐를 보고 본편으로 갈 주제를 고른다 |

> 이 스킬은 **소싱까지만 자동화**한다. "이 주제로 영상을 만들지"의 최종 결정과 사실검증은 사람이 한다. 해외 정보를 직역·무검증 적재하지 않는다.

## 기술 현실성 표

| 기능 | 상태 | 메모 |
|---|---|---|
| RSS 신규 감지 | ✅ | API 키·할당량 불필요. `feeds/videos.xml?channel_id=`. 최신 15개 제공 |
| 스케줄(cron) | ✅ | `/schedule` 루틴 또는 OS cron. 하루 1회 권장 |
| 트랜스크립트(자막) | ⚠️ | **자막 존재에 의존.** 자동자막이 없거나 자막 비공개면 추출 실패 → Whisper 폴백(무거움) 또는 스킵 |
| 현지화 번역 | ✅ | LLM이 직역 아닌 한국형 치환 수행. 사실검증은 별도(휴먼) |

## 품질 게이트 (Quality Gates)

큐에 적재하기 전 점검한다.

- [ ] **신규만 처리**했는가? (radar-state 비교 — 중복 적재 금지)
- [ ] **신선도 필터**를 적용했는가? (업로드 1개월 초과 영상은 자동 제외 — `freshness_days`)
- [ ] `뷰트랩 확인` 필드를 레코드에 **포함**했는가? (사람이 성과도·기여도를 채울 자리)
- [ ] 트랜스크립트 **출처를 비고에 명시**했는가? (자동/수동/Whisper)
- [ ] 현지화가 **직역이 아닌가?** ($→원화, 해외 도구→국내 등가물, 밈 치환)
- [ ] `한국형 핵심 문제 1문장`이 **yt-script가 바로 쓸 수 있는 1문장**인가?
- [ ] 자막 없음·신뢰 낮음 영상은 **비고에 경고**를 달았는가?
- [ ] 처리 후 `radar-state.json`을 **갱신**했는가?

## Worked Example (간결)

**모니터링 채널**: Nate Herk
**RSS로 감지된 신규 영상**: "I Built a Fully Autonomous AI Agent in n8n (Hermes)"
**자막**: 자동자막(en) 추출 성공.

**현지화 치환 결과(큐 레코드)**
```
## [2026-06-23] I Built a Fully Autonomous AI Agent in n8n (Hermes)
- 채널: Nate Herk
- URL: https://www.youtube.com/watch?v=xxxx
- 게시일: 2026-06-22T18:00:00Z
- 한국형 핵심 문제 1문장: "에이전트 만든다는데 막상 뭐부터 어떻게 자동으로 굴려야 할지 막막하다."
- 현지화 대본 초안: |
    해외에선 'n8n'으로 사람이 안 건드려도 알아서 일하는 AI 에이전트를 짜는 게 유행이다.
    한국 식으로 말하면, 외주 200만 원 줘서 시킬 일을 에이전트 하나가 24시간 대신 도는 거다.
    핵심은 도구를 많이 붙이는 게 아니라 '언제 멈추고 언제 사람을 부를지'를 정하는 설계다…
    (※ 해외 사례 금액·도구는 국내 맥락으로 치환. 완성 원고 아님 — 국내 떡상 구조는 yt-script에서 결합.)
- 뷰트랩 확인: 미확인 (🙋 크리에이터가 뷰트랩 성과도·기여도 보고 본편 여부 표기)
- 비고: 자막=자동자막(en). 업로드 6일 전(신선도 OK). 사실검증 필요: n8n 무료 한도·국내 호스팅 비용은 yt-script 단계에서 재확인.
```

이 레코드가 그대로 yt-script의 입력(이번 영상 주제 = 한국형 핵심 문제 1문장, 콘텐츠 소스 = 현지화 대본 초안)이 된다.

---

> 이 스킬은 **소싱 레이더**다. 완성 원고를 만들지 않는다(그건 yt-script). 직역·무검증 적재를 하지 않고, 신규만, 한국형으로, 검증 플래그와 함께 큐에 쌓는다.
