# yt-longform — subtract-tube 파이프라인 오케스트레이터

> 호출자: 빼기연구소 크리에이터. `/yt-longform "<주제 또는 radar 큐 항목>"`.
> 역할: 이 스킬은 **새 방법론을 만들지 않는다.** 0~10단계 하위 스킬을 **순서대로 호출**하고, 각 단계 산출물을 다음 단계 입력으로 넘기고, 휴먼 게이트에서 멈춰 승인을 받고, 실패 시 중단·재개를 관리하는 **지휘자(conductor)**다.
> 방법론 디테일은 각 SKILL.md와 [[biz-pt-longform-blueprint]] / [[practice-sheet-digest]] / [[subtract-tube-workflow]]에 있다. 이 스킬은 **순서·연동·사람 개입 지점**만 책임진다.
> 러닝 예시 주제: **"헤르메스에이전트 완벽구축하기"** (해외 n8n AI 에이전트 영상 소싱 → 한국형 현지화).

---

## When to Activate

다음 중 하나면 이 스킬을 켠다.

- 사용자가 `/yt-longform "<주제>"` 또는 `/yt-longform "<radar 큐 항목>"`을 실행할 때
- "이 주제로 영상 한 편 처음부터 끝까지 만들어줘", "radar 큐에서 이거 골라서 끝까지 가자" 류의 요청
- 개별 단계가 아니라 **end-to-end 1편 제작 흐름 전체**를 돌려야 할 때

개별 단계만 필요하면(원고만, 썸네일만 등) 그 하위 스킬을 직접 부른다. 이 스킬은 **전체 파이프라인 지휘**용이다.

---

## 입력 (Inputs)

| 입력 | 설명 | 없을 때 |
|---|---|---|
| **주제 또는 radar 큐 항목** | 만들 영상의 주제. radar 큐의 레코드(핵심문제 1문장 + 현지화 초안)를 가리키는 항목이면 1단계를 건너뛰고 그 레코드로 진입 | **필수.** 없으면 1단계(yt-radar)부터 돌려 큐를 만든 뒤 휴먼 게이트 ①에서 주제를 고르게 한다 |
| **채널 프로파일** | `yt-channel` 산출 `config/channel-profile.md`의 CHANNEL PROFILE 블록 | 캐시 없으면 0단계 먼저 실행해 1회 생성·캐시 |
| 재개 지점 | 이전 실행이 중단된 단계(있으면) | 없으면 처음부터(또는 캐시된 단계 이후부터) |

---

## 핵심 운영 원칙 (지휘 규칙)

0. **CHANNEL PROFILE이 전 단계 최상위 톤 기준.** 0단계 `yt-channel`이 만든 채널 프로파일(구독자 페르소나·니즈 / 말투·보이스 / 콘텐츠 방향성)을 매 단계 하위 스킬에 **상위 컨텍스트로 주입**한다. 특히 원고(yt-script)·현지화(yt-radar)·구조선택(yt-structure)·제목(yt-title)은 이 프로파일에 맞춰 나와야 한다. 채널 프로파일은 채널당 1회 만들고 캐시해 매 영상에서 재사용(월 1회 재학습).
1. **각 단계 산출 = 다음 단계 입력.** 한 단계의 산출물을 그대로 다음 단계에 넘긴다. 단계 간 데이터 계약은 아래 파이프라인 표의 "산출(→ 다음 입력)" 열을 따른다.
2. **실패 시 중단·재개.** 어떤 단계가 실패(연동 미설정·필수 입력 부재·API 오류)하면 **그 자리에서 중단**하고, 무엇이 왜 막혔는지·무엇을 채우면 재개되는지 보고한다. 사용자가 채운 뒤 **그 단계부터 재개**한다(완료 단계는 캐시 재사용).
3. **휴먼 게이트는 절대 자동 통과 금지.** 아래 3개 게이트에서는 반드시 멈춰 사람의 명시적 승인을 받은 뒤에만 다음으로 넘어간다.
4. **요약 금지·결(結) 일치 유지.** 원고는 절대 요약하지 않는다(yt-script 규칙). 썸네일·제목·도입부·본문·CTA가 전부 같은 핵심 문제 1문장을 향하도록 단계 간에 결을 전파한다.

---

## 휴먼 게이트 (3개 — 절대 자동화 금지)

| 게이트 | 위치 | 사람이 하는 일 | 통과 조건 |
|---|---|---|---|
| **① 뷰트랩 영상 선별** | 2~4단계(yt-structure) 진행 중 | 뷰트랩(Chrome 확장·API 없음)에서 **요소별 떡상 영상**을 사람이 직접 찾아 지정: 제목/썸네일용("구독자 낮은순인데 고조회"=구조의 힘), 도입부용("말로 된 도입부·대형채널 무관·말로 뜨는 유명인"). 본문·CTA는 제목/썸네일 영상 잠정 재사용 | 요소별 벤치마크 영상 + 스크립트 캡처가 yt-structure에 입력됨 |
| **② 원고 사실검증** | 5단계(yt-script) **직후** | 해외에서 가져온 정보(수치·도구 한도·금액 등)가 한국 맥락에서 맞는지 사람이 확인. radar `비고`의 검증 필요 항목을 여기서 푼다 | 사실 오류 없음 확인 → 원고 확정 |
| **③ 발행 승인** | 9단계(yt-seo) **전** | 제목 첫 키워드 SEO 결, 썸네일, 연령/공개 설정, 공개 시점 확인 | 사람이 "발행" 명시 승인 |

게이트에 닿으면 오케스트레이터는 **그 단계까지의 산출물을 요약 제시**하고 멈춘다. 승인/수정 지시를 받기 전엔 다음 단계를 호출하지 않는다.

---

## 파이프라인 (0~10단계 순차 호출)

각 행: **단계 → 호출 스킬 → 받는 입력 → 산출(→ 다음 입력) → 게이트**. (단계 0~9는 [[subtract-tube-workflow]]의 파이프라인과 1:1 매핑되며, 10은 분석 후 다음 영상으로의 피드백 루프다.)

| # | 단계 | 호출 스킬 | 받는 입력 | 산출 (→ 다음 입력) | 게이트 |
|---|---|---|---|---|---|
| 0 | 내 채널 분석/학습 | `yt-channel` | 내 채널 데이터(영상·지표·댓글·자막) | **채널 프로파일**(캐시) — 이후 전 단계 상위 기준 | — (검수는 사람, 1회) |
| 1 | 콘텐츠 소싱(해외) | `yt-radar` | 모니터링 채널 RSS, 채널 프로파일(현지화 니즈) | radar 큐 레코드(핵심문제 1문장 + 현지화 초안) | — |
| 2 | 제목/썸네일 구조 벤치마크 | `yt-structure` | 1의 주제 + 채널 프로파일 + 뷰트랩 선별 영상 | `① title_thumbnail` STRUCTURE TEMPLATE | **① 뷰트랩 선별** |
| 3 | 도입부 구조 벤치마크 | `yt-structure` | 2 + 뷰트랩 도입부 영상 | `② intro` STRUCTURE TEMPLATE | **① 뷰트랩 선별** |
| 4 | 본문·CTA 구조 벤치마크 | `yt-structure` | 2의 제목/썸네일 영상(잠정 재사용) | `③ body` + `④ cta` STRUCTURE TEMPLATE | **① 뷰트랩 선별** |
| 5 | 원고(짜집기) | `yt-script` | 채널 프로파일 + 1(콘텐츠) + 2·3·4(구조 4종) | 페이스리스 세그먼트 원고([나레이션]/[화면큐]) + 제목후보·설명란·고정댓글(CTA) | **② 사실검증(직후)** |
| 6 | 썸네일 | `yt-thumbnail` | 5의 핵심문제·제목후보 + `① title_thumbnail` 구조 | 썸네일 이미지 + 문구 (Higgsfield) | — (시안 선택은 사람) |
| 7 | 보이스오버(TTS) | `yt-voiceover` | 5의 `[나레이션]` 세그먼트 + 채널 프로파일(보이스) | 세그먼트별 음성 파일 | — |
| 8 | 렌더(조립) | `yt-render` | 7 음성 + 5의 `[화면큐]` + 6 썸네일 | 완성 영상 파일 (Remotion) | — (미리보기는 사람) |
| 9 | 업로드/SEO | `yt-seo` | 8 영상 + 6 썸네일 + 5 설명란/고정댓글 + 확정 제목 | 업로드된 영상 + 메타데이터 | **③ 발행 승인(전)** |
| 10 | 성과 분석 → 피드백 | `yt-analyze` | 9 업로드 결과(YouTube Analytics) | 24h 썸네일 점검 / 7d 제목 점검 리포트 → 다음 영상 디벨롭 액션 | — (디벨롭 결정은 사람) |

> 제목 디벨롭은 `yt-title`(🔶 선택)이 별도로 존재한다. 빌드되면 5(제목후보)와 6(썸네일) 사이에 끼워 확정 제목을 만들고 9에 넘긴다. 미빌드 시 5의 제목후보 중 사람이 1개 선택.

## 실행 흐름 (의사 순서)

```
1. 채널 프로파일 로드 (없으면 yt-channel 0단계 실행·캐시)
2. 입력이 radar 큐 항목이면 → 그 레코드 로드(1단계 skip)
   입력이 새 주제뿐이면 → yt-radar 실행 → [게이트①의 사전: 주제 선택]
3. yt-structure 2→3→4 호출
   ↳ 매 호출 전 [휴먼 게이트 ① 뷰트랩 선별]에서 멈춤 → 승인 후 진행
4. yt-script 5 호출 (채널 프로파일 + 콘텐츠 + 구조 4종 결합)
   ↳ 산출 직후 [휴먼 게이트 ② 사실검증]에서 멈춤 → 확정 후 진행
5. (yt-title 있으면 확정 제목) → yt-thumbnail 6 → yt-voiceover 7 → yt-render 8
   ↳ 각 단계 산출을 다음에 전달, 실패 시 중단·재개
6. [휴먼 게이트 ③ 발행 승인]에서 멈춤 → 승인 후 yt-seo 9 업로드
7. (예약) yt-analyze 10 → 리포트 → 다음 영상 피드백
```

각 단계 시작 시 "지금 N단계, 입력=…, 호출 스킬=…"를 한 줄 보고하고, 끝나면 "산출=…(다음 단계로 전달)"를 보고한다. 게이트에서는 멈춰 승인을 기다린다.

## 연동 의존성 (단계별 — 미설정 시 그 단계에서 중단)

- 0 yt-channel: YouTube Data API(검증됨) + 자막. 키 없으면 수동 export 폴백.
- 1 yt-radar: RSS(키 불필요) + youtube-transcript-api(설치됨) + cron(미설정 시 1회 수동 실행).
- 2~4 yt-structure: 뷰트랩(수동·게이트①). 자동 연동 없음.
- 5 yt-script: 외부 연동 없음(0·1·2·3·4 산출 결합만).
- 6 yt-thumbnail: Higgsfield(generate_image).
- 7 yt-voiceover: TTS 엔진/키(**미설정**).
- 8 yt-render: Remotion(Node 프로젝트, **미설정**).
- 9 yt-seo: YouTube Data API 업로드 OAuth(**미설정**).
- 10 yt-analyze: YouTube Analytics API OAuth(**미설정**).

> 런타임 연동 현황은 [[checklist]]의 (2) 연동 섹션이 단일 소스 오브 트루스. 미설정 단계에 닿으면 이 스킬은 중단하고 checklist의 해당 항목을 가리킨다.

## 품질 게이트 (오케스트레이션 레벨)

내보내기/다음 단계 진입 전 점검한다.

- [ ] **채널 프로파일이 매 단계에 주입**됐는가? (말투·니즈 최상위 기준)
- [ ] **단계 산출 = 다음 입력** 계약이 지켜졌는가? (빠진 산출물로 다음 단계를 부르지 않았는가)
- [ ] **휴먼 게이트 ①②③를 자동 통과하지 않았는가?** (각각 명시 승인 받았는가)
- [ ] **결(結) 일치**가 단계 간 전파됐는가? (썸네일·제목·도입부·본문·CTA가 핵심문제 1문장)
- [ ] **실패 단계에서 멈추고** 무엇을 채우면 재개되는지 보고했는가?
- [ ] KPI 게이트를 의식했는가? — 클릭률 10%+ / 도입부 유지 60%+ / 평균 시청 4분+ / 조회 1000+

## 출력 계약 (Output Contract)

실행 중에는 **단계별 진행 로그**(N단계 시작/산출/게이트 멈춤)를 보고한다. 1편 완료 시 아래를 요약 제시한다.

- 확정 제목 / 썸네일 / 원고 세그먼트 수 / 영상 파일 경로
- 통과한 휴먼 게이트 ①②③ 기록
- 업로드 결과(URL·공개설정) — 9단계 완료 시
- 예약된 yt-analyze 일정(24h/7d)
- 중단된 경우: **막힌 단계 + 원인 + 재개 조건**(connection 항목 가리킴)
