# yt-structure — 국내 떡상 영상 → 요소별 재사용 구조 템플릿 추출기

> 호출자: 빼기연구소 크리에이터(또는 subtract-tube 파이프라인). 사람이 뷰트랩으로 **요소별로 고른 국내 떡상 영상들**을 입력으로 넣는다(요소마다 다른 영상일 수 있다).
> 상위 입력: 0단계 `yt-channel`이 만든 **채널 프로파일**(구독자 니즈·말투·콘텐츠 방향성)이 존재한다면, 어떤 떡상 영상을 구조 소스로 고를지의 적합성 판단에 참고한다(선별은 사람 몫).
> 다운스트림 소비자: `yt-script`(① 제목/썸네일 구조·② 도입부 구조·③ 본문 구조·④ CTA 구조를 모두 소비). `yt-title`도 ① 제목/썸네일 구조를 함께 소비할 수 있다.
> 목적: 크리에이터의 실제 제작법은 **"콘텐츠(주제)는 해외 트렌드 유튜버에서, 영상 구조(틀)는 최근 떡상한 국내 유튜버(주제 무관)에서 요소별로 따로 가져와 짜집기"**다. 이 스킬은 그 **'틀' 절반**을 맡는다 — 요소마다 가장 잘하는 떡상 영상에서 구조 패턴을 **일반화된 슬롯**으로 뽑아 재사용 '구조 템플릿' 묶음을 만든다. 콘텐츠(무엇을 말할까)는 yt-radar가 따로 댄다.
> 내부 소스 오브 트루스: `knowledge/biz-pt-longform-blueprint.md`(§② 제목 디벨롭, §③ 썸네일 디벨롭, §④ 원고/도입부), `knowledge/process-v2-refined.md`(요소별 베스트 영상 소싱 모델), `knowledge/practice-sheet-digest.md`(STAGE 2 제목, STAGE 3 썸네일, STAGE 4A·4E·4F 원고). 이 스킬은 그 방법론을 자체 포함(self-contained)한다.

## 핵심 전제 — 컴포넌트 짜집기 모델에서 이 스킬의 자리

```
[콘텐츠 축] 해외 트렌드 유튜버  → yt-radar  → "무엇을 말할까"(현지화 대본/주제)
[ 틀  축 ] 국내 떡상 유튜버    → yt-structure → "어떻게 보여줄까"(구조 템플릿 묶음)  ← 이 스킬
                                  └→ yt-script (제목/썸네일·도입부·본문·CTA 구조) 가 둘을 결합(짜집기)
```

- **벤치마크는 "한 영상 통째"가 아니라 "요소별 베스트 영상 따로따로"다.** 제목/썸네일을 가장 잘 뽑은 영상, 도입부를 가장 잘 만든 영상이 서로 다른 영상일 수 있다. 각 요소를 가장 잘하는 영상에서 그 요소만 떼어 와 조합한다(컴포넌트 짜집기).
- **주제는 무관해도 된다.** 부동산 떡상 영상의 '제목 구조'를 운동 콘텐츠에 그대로 입혀도 된다. 우리가 추출하는 것은 *내용*이 아니라 *형태(구조)*다.
- **반자동(semi-automatic) — 뷰트랩은 API가 없다.** 뷰트랩의 기여도/성과도/노출확률 지표는 **Chrome 확장 오버레이**라 기계로 긁어올 수 없다. 따라서 **"어떤 떡상 영상을 어느 요소의 구조 소스로 쓸지"는 사람이 직접 선별**해 이 스킬에 넣어준다. 이 스킬은 선별된 영상(들)을 받아 요소별로 구조화하는 일만 자동화한다.

## 요소별 소싱 기준 (사람이 선별할 때 쓰는 인코딩)

각 구조 요소는 **서로 다른 떡상 영상**에서 올 수 있다. 사람이 뷰트랩으로 영상을 고를 때 적용하는 기준을 요소별로 못박는다. 이 기준은 입력 검증·신뢰도 메모에 쓰인다.

| 요소 | 어디서/어떻게 고르나 (선별 기준) | 비고 |
|---|---|---|
| **① 제목/썸네일 구조** | 뷰트랩 **핫비디오**에서, **구독자 낮은순 정렬인데 조회수가 높은** 영상 = 채널 힘이 아니라 *제목·썸네일 구조의 힘*으로 터진 것 | CTR 10%를 만든 구조 |
| **② 도입부 구조** | ① 도입부가 **말(언어)**로 된 영상 ② **대형 채널과 무관**(채널 규모가 아니라 기여도가 높은 사람) ③ **'말로 뜨는' 유명인**의 원고 도입부 | 도입부 유지율 60%를 만든 화법 |
| **③ 본문 구조** | **[잠정] 별도로 찾지 않고, 위 ① 제목/썸네일 벤치마크 영상의 본문을 그대로 따온다.** | 사용자 지시. 추후 별도 소싱 가능하게 구조를 열어둠 |
| **④ CTA 구조** | **[잠정] 별도로 찾지 않고, 위 ① 제목/썸네일 벤치마크 영상의 CTA를 그대로 따온다.** | 사용자 지시. 추후 별도 소싱 가능하게 구조를 열어둠 |

> **잠정 규칙(사용자 확정):** "b로 진행하자. 본문 + CTA 기준은 일단 좋은 제목/썸네일 구조를 벤치마크한 영상꺼를 따오는 쪽으로 우선 설계하자." → ③ 본문·④ CTA는 지금은 ① 제목/썸네일 영상을 **재사용**한다. 단, 출력에서 `source`를 별도 필드로 분리해 두어, 나중에 본문·CTA 전용 벤치마크 영상이 생기면 그 자리만 갈아끼우면 되게 한다.

## When to Activate

다음 중 하나면 이 스킬을 켠다.

- 사용자가 **"이 (국내) 떡상 영상들의 틀/구조를 뽑아줘"**, "요소별로 벤치마크 잡아줘", "이 영상 구조 템플릿으로 만들어줘" 류로 요청할 때
- subtract-tube 파이프라인에서 주제 발굴(yt-radar) 이후, 원고 작성(yt-script) **이전**의 구조화 단계에 진입할 때
- 사람이 뷰트랩에서 **요소별 떡상 영상**(제목/썸네일용, 도입부용)을 캡처/링크/스크립트로 확보해 "이걸로 틀 잡자"고 넘길 때

해외 트렌드 영상에서 **주제·내용**을 가져오는 것은 이 스킬이 아니라 `yt-radar`의 몫이다. 이 스킬은 **국내 떡상 영상의 구조(틀)만** 다룬다.

## 입력 (Inputs)

사람이 뷰트랩 기여도/성과도로 **이미 선별한 국내 떡상 영상들**을 받는다. **요소마다 다른 영상일 수 있다.** 주제는 내가 만들 영상과 달라도 된다.

### A. 제목/썸네일 벤치마크 영상 (필수) — ①의 소스, 잠정 ③④의 소스도 겸함

| 입력 | 설명 | 없을 때 |
|---|---|---|
| **떡상 영상 제목** | 원문 그대로 | **필수.** 없으면 진행 불가 |
| **썸네일 정보** | 썸네일에 박힌 **카피 문구** + 이미지 구성 묘사(인물/비포애프터/확대/증명자료 등) | 카피 문구는 필수. 이미지 묘사 없으면 1회 질문 |
| **본문 흐름**(잠정) | 이 영상이 어떤 섹션 순서로 전개되는지(목차/챕터/체감 흐름) — ③ 본문 구조의 소스 | 트랜스크립트 있으면 정확. 없으면 챕터·댓글·제목으로 추정 `(inferred)` |
| **CTA/마무리**(잠정) | 이 영상이 끝에서 어떻게 행동을 유도하는지(고정댓글·다음 영상·링크 등) — ④ CTA 구조의 소스 | 없으면 기본 CTA 패턴으로 추정 `(inferred)` |
| (선택) 떡상 근거 | 뷰트랩 기여도/성과도/노출확률 수치, 조회수, 구독자수 | 없어도 됨. 있으면 신뢰도 메모에 기록 |

### B. 도입부 벤치마크 영상 (별도 영상일 수 있음) — ②의 소스

| 입력 | 설명 | 없을 때 |
|---|---|---|
| **도입부 스크립트** | 영상 첫 10~30초 대사 원문(또는 받아쓰기) — **'말로 된' 도입부**여야 함 | 없으면 A영상의 도입부로 대체하거나, 제목+썸네일로 **역설계**하고 `(inferred)` 표기 |
| **도입부 출처 메모** | 대형 채널과 무관/기여도 높은 사람/'말로 뜨는' 유명인 중 어디에 해당하는지 | 없으면 사용자에게 1회 질문 |
| (선택) 도입부 근거 | 도입부 유지율, 조회수, 구독자수 | 없어도 됨 |

> **A와 B는 같은 영상일 수도, 다른 영상일 수도 있다.** 둘 다 입력으로 받되, 같으면 `source`가 같게 적힌다.
> **트랜스크립트가 있으면 정확도가 크게 오른다.** 없는 부분은 `confidence: inferred`로 명시한다.
> 모든 입력은 "사람이 뷰트랩 지표로 떡상이라 판단해 선별했다"는 전제 위에서 신뢰한다(스킬은 떡상 여부를 재판정하지 않는다).

## 추출 방법론 — 요소를 '슬롯'으로 일반화

각 구조는 **원문 그대로 적기 → 변하지 않는 골격(슬롯)으로 추상화 → 비즈니스PT 방법론과 매핑**의 3단계로 뽑는다. 핵심은 "이 영상 *내용*을 베끼는 게 아니라 *형태*만 슬롯으로 남기는 것"이다. **각 요소는 자기 source 영상에서만 뽑는다**(요소별 소싱).

### ① 제목/썸네일 구조 (A영상에서)

제목과 썸네일 카피를 함께 슬롯화한다. 둘은 한 쌍으로 CTR을 만든다.

**썸네일 카피** — 썸네일에 박힌 **문구**를 슬롯화한다. (이미지 구성은 6원칙 메모로 부기 — blueprint §③: 확대 / 시각적 증명자료 / 신뢰 인물 / 궁금증 / 타겟 선호 / 비포애프터.)
- 원문 예: "넓은 어깨는 어떻게 만들어지는가?"
- 슬롯: `[대상/목표] + [어떻게 ~되는가? / 의문형 후킹]`

**제목** — blueprint §② 제목 4법(동일주제 문구조합 / 쉬운 동의어 / 상위어 확장 / 수식어 강조)과 매핑하고, digest STAGE 2A의 **교차조합**(좋은 썸네일 문구↔내 제목 교차)을 어느 칸에서 끌어올 수 있는지 표시한다.
- 원문 예: "10년간 311경기를 뛴 제가 증명한, 평범한 몸이 미친 체력으로 바뀌는 3가지 방법"
- 슬롯: `[개인가치/권위 수식어] + [평범한 대상] + [충격적 변화/결과] + [숫자 N가지]`
- 권위 슬롯이 있으면 yt-script가 그 자리에 크리에이터 이력(개인가치)을 넣는다.

### ② 도입부 구조 (B영상에서 — 가장 중요)

도입부의 첫 임무는 **제목/썸네일이 만든 클릭 기대감을 첫 문장으로 그대로 이어받는 것**이다(결 일치의 시작점). 도입부를 슬롯으로 뽑되, 반드시 다음 두 가지와 매핑한다.

- **후킹 공식**(blueprint §④): 사전신호(기대감 조성) → 예측오류 → 인지적 명료성
- **도입부 3요소**: 문제제기 · 사례 · 유인(보상/약속)

일반화 슬롯 예:
```
도입부 = [제목·썸네일 기대감 재진술] → [예측오류/반전] → [약속(유인)]
```
- 원문 예(고양이 신부전): "여러분, 혹시 고양이 신부전 때문에 가슴 아파보신 적…? 사망원인 1위… 물그릇 바꿔도 소용없다는 거 아세요?… 1%의 집사만 아는 기적의 방법 딱 5가지!"
- 슬롯: `[문제제기(공감)] → [기존통념 부정=예측오류] → [희소성+약속 "1%만 아는 N가지"]`
- **결 일치 메모**: 이 도입부가 ①의 어떤 문구를 첫 문장에서 재진술하는지 명시해, yt-script가 도입부를 골격으로 쓸 때 제목·썸네일과 결을 끊지 않게 한다.

### ③ 본문 구조 (잠정: A영상 재사용)

영상 전체를 **순서 있는 섹션 슬롯**으로 뽑는다. **현재는 ① 제목/썸네일 벤치마크 영상(A)의 본문 흐름을 그대로 소스로 쓴다**(잠정 규칙). blueprint §④ 원고 6구성(도입부 → 정보 → 개인가치2 → 결론 → 추천 → 기대감)을 기준자로 삼아, A영상의 실제 흐름을 그 위에 매핑(또는 변형)한다.

- 각 섹션에 대해: `섹션명 | 역할(공감/정보/신뢰/전환/CTA) | 대략 분량비중 | 이 섹션이 쓰는 후킹·전환 장치`
- 트랜스크립트 없으면 챕터/댓글 기반 추정으로 채우고 `(inferred)` 표기.
- **출력에 `source=제목/썸네일영상(잠정)`을 명시**해, 추후 본문 전용 벤치마크가 생기면 이 자리만 교체 가능하게 둔다.

### ④ CTA 구조 (잠정: A영상 재사용)

영상이 끝에서 행동을 어떻게 유도하는지 슬롯화한다. **현재는 ① 제목/썸네일 벤치마크 영상(A)의 CTA를 그대로 소스로 쓴다**(잠정 규칙).

- 슬롯 예: `[또 다른 문제제기] → [다음/키 콘텐츠 유도] → [고정댓글 행동제시(링크/증거자료)]`
- 증거자료형/휘발성형 중 어느 패턴인지 메모.
- **출력에 `source=제목/썸네일영상(잠정)`을 명시**해, 추후 CTA 전용 벤치마크가 생기면 이 자리만 교체 가능하게 둔다.

---

## 출력 계약 (Output Contract) — 요소별 '구조 템플릿' 묶음

아래 `STRUCTURE TEMPLATE` 블록을 산출한다. **`yt-script`가 파싱 없이 그대로 소비**(① 제목/썸네일도 `yt-title`이 함께 소비 가능)한다. 슬롯의 `[...]`는 채워질 빈칸이고, `confidence`는 confirmed(원문 확인) / inferred(추정)로 표기한다. **각 요소에 자기 `source`(어느 영상에서 왔는가)를 박는다** — 요소마다 다를 수 있으며, ③④는 `source=제목/썸네일영상(잠정)`을 명시한다.

```
## STRUCTURE TEMPLATE
sources:
  title_thumbnail: { title: "<A 영상 원제목>", topic: "<원본 주제(무관)>", picked_by: "human/viewtrap(핫비디오·구독자낮은순 고조회)", transcript: yes|no, metrics: "<있으면 수치>" }
  intro:           { title: "<B 영상 원제목 — A와 같을 수도 다를 수도>", topic: "<원본 주제>", picked_by: "human/viewtrap(말로된 도입부·대형채널무관·말로뜨는유명인)", transcript: yes|no, metrics: "<있으면 수치>" }
  body:            "제목/썸네일영상(잠정)"   # 추후 본문 전용 벤치마크로 교체 가능
  cta:             "제목/썸네일영상(잠정)"   # 추후 CTA 전용 벤치마크로 교체 가능

# ① title_thumbnail  → consumed by: yt-script (+ yt-title)
source: title_thumbnail
thumbnail_copy:
  slots: [<슬롯들>]                  # 예: ["[지시대명사 은폐: 이것]","[충격 결과]"]
  verbatim: "<원문 썸네일 카피>"
  image_notes: "<6원칙 중 적용된 것 — 확대/증명/인물/궁금/선호/비포애프터>"
title:
  slots: [<슬롯들>]                  # 예: ["[개인가치 수식어]","[평범한 대상]","[충격 변화]","[숫자 N가지]"]
  verbatim: "<원제목>"
  maps_to: "제목 4법 중 [동일주제 문구조합|쉬운 동의어|상위어 확장|수식어 강조] / 교차조합 가능 칸"
confidence: confirmed|inferred

# ② intro  → consumed by: yt-script
source: intro
slots: [<순서 슬롯>]                  # 예: ["[제목·썸네일 기대감 재진술]","[예측오류]","[약속(유인)]"]
hook_formula: "사전신호 → 예측오류 → 인지적 명료성"   # 도입부 영상이 실제로 밟은 형태로 채움
intro_3elements: { 문제제기: "...", 사례: "...", 유인: "..." }
ties_to: "①의 어느 문구를 첫 문장에서 재진술하는가(결 일치 시작점)"
verbatim: "<도입부 원문 또는 역설계>"
confidence: confirmed|inferred

# ③ body  → consumed by: yt-script
source: 제목/썸네일영상(잠정)        # 사용자 지시: 본문은 ① 영상 본문을 재사용. 추후 교체 가능
flow:
  - { name: "...", role: "공감|정보|신뢰|전환|CTA", weight: "~%", device: "쓰인 후킹/전환 장치" }
  - ...
maps_to: "원고 6구성(도입부→정보→개인가치2→결론→추천→기대감) 대비 정렬/변형 메모"
confidence: confirmed|inferred

# ④ cta  → consumed by: yt-script
source: 제목/썸네일영상(잠정)        # 사용자 지시: CTA는 ① 영상 CTA를 재사용. 추후 교체 가능
slots: [<순서 슬롯>]                  # 예: ["[또 다른 문제제기]","[다음/키 콘텐츠 유도]","[고정댓글 행동제시]"]
pattern: "증거자료형|휘발성형"
verbatim: "<마무리/CTA 원문 또는 역설계>"
confidence: confirmed|inferred

# 결(結) 일치 체크 — 요소들이 한 흐름으로 이어지는가
consistency: "①의 기대감 → ② 첫 문장 재진술 → ③ 전개 → ④ CTA가 같은 결로 흐르는지 한 줄 평(요소 source가 달라도 결은 하나여야 함)"
```

**소비 계약(누가 무엇을 가져가는가):**
- `yt-script` ← **네 요소 전부**를 골격으로 사용: `①title_thumbnail`(제목·썸네일 슬롯), `②intro`(도입부 골격), `③body.flow`(전체 섹션 골격), `④cta`(마무리·행동제시 골격). 골격은 이 템플릿에서, 내용은 yt-radar 해외 현지화 대본에서 가져와 결합한다.
- `yt-title`(있으면) ← `①title_thumbnail`을 채워 제목·썸네일 카피를 생성.

## 품질 게이트 (Quality Gates)

구조 템플릿을 내보내기 전 점검한다. 하나라도 실패하면 고쳐 다시 통과시킨다.

- [ ] 네 요소(① 제목/썸네일 ② 도입부 ③ 본문 ④ CTA)가 모두 슬롯으로 추출됐는가?
- [ ] **각 요소에 자기 `source`가 박혔는가?** ③④는 `source=제목/썸네일영상(잠정)`으로 명시됐는가?
- [ ] ① 제목/썸네일 source 영상이 **구독자 낮은순인데 고조회**(구조의 힘) 기준으로 선별됐다는 게 `picked_by`에 박혔는가?
- [ ] ② 도입부 source 영상이 **말로 된 도입부 / 대형채널 무관 / 말로 뜨는 유명인** 기준으로 선별됐다는 게 `picked_by`에 박혔는가?
- [ ] 슬롯이 **내용이 아니라 형태(골격)**인가? (원본 주제 명사가 슬롯에 박혀 있으면 안 됨 — `verbatim`에만 남긴다)
- [ ] ② 도입부 슬롯이 **①의 기대감을 첫 문장에서 재진술**하도록 `ties_to`가 채워졌는가? (결 일치 시작점)
- [ ] ② 도입부에 후킹 공식(사전신호→예측오류→인지적 명료성) + 도입부 3요소가 매핑됐는가?
- [ ] ① 제목이 제목 4법 중 무엇에 해당하는지 `maps_to`에 표기됐는가?
- [ ] 트랜스크립트 없는 부분은 `confidence: inferred`로 정직하게 표기했는가?
- [ ] 반자동 전제(뷰트랩 no-API, 떡상 영상은 사람이 요소별로 선별)가 `sources.*.picked_by`에 박혀 있는가?

## Worked Example (간결)

**입력(사람이 뷰트랩으로 요소별 선별):**
- **A 제목/썸네일 영상:** 운동 채널 "어깨 넓히는 법"(8만뷰, 구독자 낮은순 정렬에서 고조회, 트랜스크립트 있음) — 본문·CTA도 잠정 이 영상에서 따옴.
- **B 도입부 영상:** 자기계발 유명인 강연 클립("말로 뜨는" 유명인, 대형채널 무관) — 도입부만 떼어 옴.
- 내가 만들 영상 주제는 *부동산*이어도 무관.

```
## STRUCTURE TEMPLATE
sources:
  title_thumbnail: { title: "이것 하나로 어깨가 벌어졌습니다", topic: "운동/어깨", picked_by: "human/viewtrap(핫비디오·구독자낮은순 고조회)", transcript: yes, metrics: "8만뷰/저구독" }
  intro:           { title: "당신이 못 바뀌는 진짜 이유", topic: "자기계발", picked_by: "human/viewtrap(말로된 도입부·말로뜨는유명인·대형채널무관)", transcript: yes, metrics: "조회 30만/기여도 높음" }
  body:            "제목/썸네일영상(잠정)"
  cta:             "제목/썸네일영상(잠정)"

# ① title_thumbnail  → consumed by: yt-script (+ yt-title)
source: title_thumbnail
thumbnail_copy:
  slots: ["[지시대명사 은폐: 이것]","[충격 결과: 대상이 바뀜]"]
  verbatim: "이것 하나로 어깨가 벌어졌습니다"
  image_notes: "비포애프터(좁→넓) + 확대"
title:
  slots: ["[평범한 대상]","[충격 변화]","[숫자 N가지]"]
  verbatim: "헬스장만 다니던 평범한 사람이 어깨 벌어진 3가지 방법"
  maps_to: "수식어 강조 + 동일주제 문구조합 / 썸네일 '이것 하나로'를 내 제목에 교차 가능"
confidence: confirmed

# ② intro  → consumed by: yt-script  (※ A와 다른 영상에서 옴)
source: intro
slots: ["[제목·썸네일 기대감 재진술]","[예측오류]","[약속(유인)]"]
hook_formula: "다들 더 노력하라고 한다(사전신호) → 근데 노력으로 안 된다(예측오류) → 딱 한 가지만 바꾸면 된다(인지적 명료성)"
intro_3elements: { 문제제기: "아무리 해도 안 바뀜", 사례: "화자 본인의 실패담", 유인: "1%만 아는 한 가지" }
ties_to: "A 썸네일 '이것 하나로'를 B 도입부 골격의 첫 문장에 이식해 재진술"
verbatim: "다들 더 노력하라고 하죠. 근데 저는 노력으로 안 됐습니다. 딱 한 가지를 바꾸고 나서야…"
confidence: confirmed

# ③ body  → consumed by: yt-script
source: 제목/썸네일영상(잠정)
flow:
  - { name: "도입부", role: "공감", weight: "~15%", device: "언더독 후킹 + 비포애프터" }
  - { name: "핵심정보", role: "정보", weight: "~45%", device: "무게가 아니라 각도(통념 반전)" }
  - { name: "권위/사례", role: "신뢰", weight: "~20%", device: "국내사례 치환 + 원본캡처" }
  - { name: "마무리", role: "전환/CTA", weight: "~20%", device: "또 다른 문제제기 → 고정댓글" }
maps_to: "원고 6구성과 거의 정렬, 개인가치 2절은 '권위/사례'로 압축됨"
confidence: confirmed

# ④ cta  → consumed by: yt-script
source: 제목/썸네일영상(잠정)
slots: ["[또 다른 문제제기]","[다음/키 콘텐츠 유도]","[고정댓글 행동제시(링크)]"]
pattern: "증거자료형"
verbatim: "어깨 다음은 등입니다. 등 벌어지는 법은 고정댓글 링크에 정리해뒀어요. 영상 끝나면 바로 확인하세요."
confidence: confirmed

consistency: "A 썸네일 '이것 하나로' → B 도입부 골격 첫 문장에 이식·재진술 → 정보에서 '이것=각도' 공개 → CTA까지 한 결로 이어짐. (요소 source는 A·B로 갈렸지만 결은 하나) ✔"
```

이 템플릿의 **슬롯**만 부동산 콘텐츠(yt-radar 해외 현지화 대본)로 채우면, 주제는 부동산이되 요소별 떡상 영상의 *틀*을 그대로 입은 영상이 된다.

---

> 이 스킬은 "구조(틀)만 추출"한다는 원칙에 충실해야 한다. 떡상 영상의 *내용·주제*를 베끼지 말 것 — 슬롯(형태)만 남기고 내용은 `verbatim`에만 보관한다. 모든 산출물은 요소별 소싱(요소마다 source 명시)·③④ 잠정 재사용 규칙·결 일치·반자동(뷰트랩 no-API) 전제를 지킨다.
